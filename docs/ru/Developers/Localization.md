# BIOMASHINE: локализация

Как устроены области словарей, реестр языков, инструмент `npm run i18n` и правила множественных форм, и как добавить новый язык, не касаясь кода главного процесса.

## 1. Обзор

Каждая видимая пользователю строка в BIOMASHINE лежит в JSON-словаре. Каждый словарь — это плоский объект, отображающий ключ в строку или в набор форм множественного числа:

```json
{
  "hello": "Привет, {name}!",
  "count": { "one": "{count} запись", "other": "{count} записи" }
}
```

Есть четыре области словарей:

| Область | Расположение | Кем используется |
|---|---|---|
| `shell` | `src/renderer/shell/locales` | Оболочка (`bm://app/shell`) |
| `shared` | `src/renderer/shared/locales` | Всеми областями: единицы измерения, общие кнопки, названия тем и достижений |
| `backend` | `src/main/locales` | Главный процесс: сообщения `AppError`, проблемы в конфигах, модулях и словарях |
| модуль `<id>` | `<папка модуля>/locales` | Этим модулем (только когда в его `manifest.json` стоит `"i18n": true`) |

`LocaleService` собирает набор строк для области и языка и передаёт его оболочке (`i18n:bundle`), модулю (в его сообщении `init`) и главному процессу (`MessageService`). Порядок обхода описан в разделе 3.

## 2. Реестр языков (`i18n.builtin`)

`config/app.json` → `i18n.builtin` — источник правды о том, какие языки программа поддерживает из коробки:

```json
"i18n": {
  "directory": "locales",
  "default": "en",
  "reference": "ru",
  "source": "en",
  "required": ["ru", "en"],
  "builtin": [
    { "code": "ru", "name": "Русский", "locale": "ru-RU" },
    { "code": "en", "name": "English", "locale": "en-US" }
  ],
  "codePattern": "^[a-z]{2,3}(-[A-Za-z0-9]{2,8})?$",
  "pluralForms": ["zero", "one", "two", "few", "many", "other"]
}
```

| Поле | Смысл |
|---|---|
| `default` | Язык, используемый, когда лучшего варианта нет. |
| `reference` | Словарь, с которым сравниваются все остальные. Новая запись в `reference` делает все остальные языки «неполными», пока запись не появится и в них. |
| `source` | Язык, из которого берутся значения для новых переводов (`npm run i18n -- add <code> … --from en`). |
| `required` | Языки, словарь для которых обязателен в каждой области. `tests/moduleContract.test.js` и `npm run i18n -- check` обеспечивают это. |
| `builtin` | Реестр поставляемых языков: код, отображаемое имя, локаль BCP 47. |
| `codePattern` | Регулярное выражение для кода языка. |
| `pluralForms` | Набор имён форм множественного числа, допустимых в словаре. |

Список `builtin` читают:

- `LocaleService.languages()` — список языков, показываемый в настройках.
- `LocaleService.detect(systemLocale)` — исходный язык при первом запуске.
- `scripts/i18n.js` — все команды инструмента.
- `tests/support/I18nScan.js` — все тесты словарей.

Добавить язык в `i18n.builtin` достаточно, чтобы оболочка, модули и тесты про него узнали.

## 3. Цепочка запасных языков

Для области, языка и ключа `LocaleService` собирает строки в таком порядке:

1. Область `shared` каждого языка в цепочке (только когда текущая область — не `shared` и не `backend`).
2. Собственный словарь области.

Сама цепочка: выбранный язык → `meta.fallback` языка (для пользовательских языков) → `default` → все языки из `builtin`. Дубликаты удаляются.

Если ключ всё ещё не найден, `bm.t` и `MessageService.t` возвращают сам ключ. Именно поэтому старая русская строка в контроллере продолжает работать во время миграции: записи в словаре нет, но ключ — это и есть текст.

## 4. Обязательные и необязательные языки

`i18n.required` определяет, какие языки обязательны в каждой области. По умолчанию `["ru", "en"]`:

- **Обязательные**: каждая область (включая каждый модуль с `"i18n": true`) должна иметь полный файл. Отсутствующий ключ роняет `npm test` и `npm run i18n -- check`.
- **Необязательные**: другие встроенные языки могут отсутствовать в какой-то области. Если файл для такого языка присутствует, он проходит ту же проверку полноты, что и эталонный язык — частичный файл это ошибка, а не запасной вариант.

Цепочка запасных языков добирает недостающие ключи в рантайме, но `tests` и `npm run i18n -- check` говорят «нет»: каждый словарь обязан быть полным относительно `i18n.reference`.

## 5. Инструмент `npm run i18n`

`node scripts/i18n.js <command>` (или `npm run i18n -- <command>`) ведёт весь процесс. Каждая команда — тонкая обёртка над классом `I18nTool`; тесты работают с классом напрямую на временных каталогах.

### `status [--source en] [--json]`

Печатает таблицу «область × язык».

```
Source: en, reference: ru
Scope: backend
  ru  src/main/locales/ru.json  keys=120 missing=0 extra=0 untranslated=0
  en  src/main/locales/en.json  keys=120 missing=0 extra=0 untranslated=0
Scope: shell
  ru  src/renderer/shell/locales/ru.json  keys=140 missing=0 extra=0 untranslated=0
  en  src/renderer/shell/locales/en.json  keys=140 missing=0 extra=0 untranslated=2
Totals:
  ru  100%   keys=260 missing=0 extra=0 untranslated=0
  en  99.2%  keys=260 missing=0 extra=0 untranslated=2
```

- `missing` — ключи из `reference`, отсутствующие в этом файле.
- `extra` — ключи файла, отсутствующие в `reference`.
- `untranslated` — значения, совпадающие с `source`. Для самих `reference` и `source` не считаются.
- `--source xx` — сравнение с другим источником.
- `--json` — полная структура (используется тестами).

### `files <code> [--missing]`

Перечисляет каждую область с файлом словаря для этого языка:

```
[exists] src/main/locales/en.json (120 keys, 0 missing)
[exists] src/renderer/shell/locales/en.json (140 keys, 0 missing)
[exists] src/renderer/shared/locales/en.json (45 keys, 0 missing)
[create] src/renderer/modules/reaction/locales/en.json (0 keys, 32 missing)
```

- `[exists]` — файл уже есть.
- `[create]` — файла нет, его нужно создать.
- `--missing` — только записи, требующие работы.

### `add <code> "<Name>" <locale> [--fallback en] [--from en]`

Регистрирует новый встроенный язык и создаёт файлы-заготовки.

1. Проверяет `code` и `locale` по `i18n.codePattern`.
2. Отказывается, если язык уже есть в `i18n.builtin` или в `userData/locales`.
3. Пишет `config/app.json` с новой записью в `i18n.builtin` (включая `fallback`).
4. Для каждой области копирует строки языка `--from` (по умолчанию `source`) и разворачивает формы множественного числа в точный набор категорий из `Intl.PluralRules(locale)`. Значение вида `{ "one": "…", "other": "…" }` из английского становится нужным набором для немецкого (`one`, `other`), польского (`one`, `few`, `many`, `other`), арабского (`zero`, `one`, `two`, `few`, `many`, `other`) и так далее.

```
$ npm run i18n -- add de "Deutsch" de-DE
Добавлен язык de (Deutsch, de-DE), файлов: 3, ключей: 187
  src/main/locales/de.json (120)
  src/renderer/shell/locales/de.json (45)
  src/renderer/shared/locales/de.json (22)
```

### `check [code] [--allow-missing]`

Проверяет каждый словарь относительно эталона. Проверяет:

- **Подстановки** `{…}` точно совпадают с эталоном (те же имена, то же количество).
- **Формы множественного числа** — это ровно набор `Intl.PluralRules(locale).resolvedOptions().pluralCategories`: ни больше, ни меньше, без пустых значений.
- **Пустые строки** — пустое значение это ошибка.
- **Лишние ключи** — каждый ключ должен быть в эталоне.
- **Отсутствующие ключи** — каждый эталонный ключ должен присутствовать (если не указан `--allow-missing`).

Код выхода — `1`, когда найдены проблемы:

```
$ npm run i18n -- check de
src/renderer/shell/locales/de.json [items]: нет форм: other
src/renderer/shell/locales/de.json [items]: подстановки не совпадают с ru: ожидалось [count], получено [n]
src/main/locales/de.json: нет ключа относительно ru
```

Без `<code>` инструмент проверяет все языки.

## 6. Как добавить язык

Шесть шагов. Ничего вне файлов словарей и `config/app.json` не трогается.

### 6.1. Добавить язык

```
npm run i18n -- add de "Deutsch" de-DE --fallback en --from en
```

Команда регистрирует `de` в `i18n.builtin` и заполняет каждую область английскими строками. Начинать с другого языка (`--from ru`) тоже можно, если переводчику так удобнее.

### 6.2. Посмотреть, что нужно перевести

```
npm run i18n -- files de --missing
```

Показывает ровно те файлы, которые нужно перевести. Каждая запись с `[create]` или с `missing > 0` — файл в работу.

### 6.3. Перевести файлы

Откройте каждый файл из списка и замените значения. Ключи оставьте как есть. Если в значении есть `{placeholders}` — сохраните их. Если значение — объект множественного числа, сохраните имена форм.

Пример — `src/renderer/shell/locales/de.json`:

```json
{
  "nav.settings": "Einstellungen",
  "items": { "one": "{count} Eintrag", "other": "{count} Einträge" }
}
```

Пользовательский язык можно просто положить в `userData/locales` (раздел 7) — пересборка не нужна.

### 6.4. Проверить

```
npm run i18n -- check de
```

Исправьте каждую найденную проблему. Когда команда напечатает `Проблем не найдено`, язык готов. `--allow-missing` полезен посреди перевода, чтобы видеть только остальные категории проблем.

### 6.5. Шрифты и письменности

Пакеты `@fontsource/jetbrains-mono` и `@fontsource/playfair-display` содержат следующие подмножества по умолчанию:

| Категория | Письменности | Покрытие |
|---|---|---|
| Встроенные | латиница, расширенная латиница, кириллица | `config/app.json` → `fonts.subsets = ["latin", "latin-ext", "cyrillic"]` |
| Через конфиг | греческий, вьетнамский | добавьте `"greek"` или `"vietnamese"` в `fonts.subsets` и запустите `npm run prepare-assets -- --force` |
| Системные | китайский, японский, корейский, арабский, иврит, тайский, деванагари и все прочие письменности | Chromium выбирает системный шрифт из ОС. Настраивать нечего: цепочка шрифтов в `base.css` заканчивается на `monospace`/`serif`, поэтому браузер берёт шрифт, покрывающий письменность |

Самая важная часть — хвосты `--font-mono` и `--font-serif` в `src/renderer/shared/base.css`:

```css
--font-mono: 'JetBrains Mono', ui-monospace, SFMono-Regular, Menlo, Consolas,
             'Liberation Mono', 'DejaVu Sans Mono', monospace;
--font-serif: 'Playfair Display', ui-serif, Georgia, Cambria, 'Times New Roman', serif;
```

`tests/assets.test.js` проверяет это — `font-family` без generic-семейства в конце роняет тест.

Если язык требует письменность, которой нет в поставляемых шрифтах, и системного по умолчанию недостаточно, добавьте подмножество в `fonts.subsets` и перезапустите `npm run prepare-assets -- --force`. Для письменностей, которых нет в `@fontsource` (CJK, арабский, тайский, деванагири), добавьте локальный шрифт через плагин (`PLUGIN_GUIDE.md` → раздел про `@font-face`); внешние URL недоступны, потому что приложение офлайновое.

### 6.6. Тестировать

```
npm test
```

Вся тестовая сюита знает о языках:

- `tests/support/I18nScan.js` обходит `i18n.builtin`.
- `tests/moduleContract.test.js` требует полный файл для каждого языка из `i18n.required` у каждого модуля, а если файл для другого встроенного языка присутствует — полный файл и для него.
- `tests/translator.test.js` содержит тест с воображаемым `de`, который доказывает, что проверки управляются реестром, а не захардкожены.

Если ключа в новом языке не хватает, сообщение указывает точный файл и ключ.

## 7. Пользовательские языки (`userData/locales`)

Пользователь может положить язык в `userData/locales/<code>.json`, не трогая `config/app.json`. Такой файл патчит (для `ru` и `en`) или добавляет (для любого другого кода) словари.

```json
{
  "meta": { "code": "de", "name": "Deutsch", "locale": "de-DE", "fallback": "en" },
  "scopes": {
    "shell": { "nav.settings": "Einstellungen" },
    "shared": {},
    "backend": { "error.locked": "Anmeldung erforderlich" },
    "reaction": {}
  }
}
```

- `meta.code` должен соответствовать `codePattern`. `meta.name` — имя, показываемое в настройках. `meta.locale` — локаль BCP 47 для `Intl`. `meta.fallback` — язык, к которому обращаться, если ключ отсутствует.
- `scopes` может содержать любое подмножество областей. Отсутствующая область — не ошибка.
- Пользовательский язык с `meta.code`, равным `ru` или `en`, **патчит** встроенные строки, а не добавляет язык. Так пользователь переопределяет отдельную строку, не форкая приложение.
- Настройки экспортируют шаблон (`i18n:export`) со всеми областями и всеми ключами. Переводчику достаточно положить результат в `userData/locales`, перевести значения, сохранить `meta` — и всё.
- Проблемы (некорректный JSON, отсутствие `meta`, некорректные объекты множественного числа) показываются в настройках → «Языки». `npm run i18n -- check` пользовательские языки не проверяет (они вне репозитория), но `LocaleService.errors()` — да.

## 8. Формы множественного числа (CLDR)

Значение множественного числа — это JSON-объект, ключи которого — категории CLDR:

```json
{ "one": "{count} запись", "few": "{count} записи", "many": "{count} записей", "other": "{count} записи" }
```

Категорию выбирает `Intl.PluralRules(locale).select(count)`. Какие категории использует каждый язык:

| Язык | Категории | Пример для `count = 1, 2, 5, 21` |
|---|---|---|
| `en`, `de`, `nl`, `sv` | `one`, `other` | `item`, `items`, `items`, `items` |
| `ru`, `uk`, `pl`, `cs` | `one`, `few`, `many`, `other` | `запись`, `записи`, `записей`, `запись` |
| `ar` | `zero`, `one`, `two`, `few`, `many`, `other` | шесть отдельных форм |
| `fr`, `pt-BR` | `one`, `many`, `other` | `article`, `articles`, `articles` |
| `ja`, `zh`, `ko` | `other` | `項目` |
| `tr`, `hu` | `one`, `other` | `öğe`, `öğe` |

Инструмент выводит это из `Intl.PluralRules` — категории языка никогда не захардкожены. `npm run i18n -- add` заполняет правильный набор, `npm run i18n -- check` отклоняет слишком маленький или слишком большой набор, а `MessageTranslator`/`Translator` выбирают нужную форму в рантайме.

## 9. Чек-лист релиза с новым языком

Перед выпуском нового встроенного языка:

- [ ] `npm run i18n -- add <code> "<Name>" <locale>` — запись в `i18n.builtin` есть, файлы-заготовки созданы.
- [ ] `npm run i18n -- files <code> --missing` — все файлы переведены.
- [ ] `npm run i18n -- check <code>` — проблем нет.
- [ ] `npm run i18n -- status` — новый язык на `100%` в блоке «Totals».
- [ ] `npm test` — проходит; если модуль добавили после языка, контрактный тест модуля создаст недостающий файл.
- [ ] `config/app.json` → `i18n.builtin` содержит новый язык с правильной `locale`.
- [ ] Если языку нужна письменность вне `latin`/`latin-ext`/`cyrillic`, `fonts.subsets` обновлён и `npm run prepare-assets -- --force` выполнен.
- [ ] `CHANGELOG.md` (если есть) упоминает язык.
- [ ] GitHub release notes перечисляют язык.

## 10. Кто где читает строки

- **Главный процесс** — `MessageService.t(key, params)`. Язык берётся из `SettingsService`, поэтому смена применяется без перезапуска. `AppError` несёт ключ и параметры; `IpcRouter` переводит перед ответом.
- **Оболочка** — `ShellApp` получает пакет строк из `i18n:bundle` и передаёт его в `Translator`; `data-i18n`-атрибуты заполняет `DomTranslator`.
- **Модули** — пакет приходит в сообщении `init` и доступен как `bm.t(key, params)`. `bm.locale` даёт локаль BCP 47 для `toLocaleString`.
- **Тесты** — `tests/support/I18nScan.js` проверяет словари напрямую; от рантайма он не зависит.
