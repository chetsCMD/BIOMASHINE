# BIOMASHINE: Система модулей

Всё на экране, кроме оболочки, является модулем. Этот документ — контракт для написания модуля: формат манифеста, модель изоляции, SDK, который видит модуль, хранилище, локализация, время, темы и плагины. Об окружающей архитектуре см. [Project Map.md](Project%20Map.md).

## 1. Виды модулей

| Тип | Что это | Расположение |
|---|---|---|
| Страница (`page`) | Экран с собственным пунктом меню, UI и данными | `src/renderer/modules/<id>/` (системный), `userData/modules/<id>/` (пользовательский) |
| Плагин (`plugin`) | Только CSS, применяется к оболочке и к каждой странице | те же расположения |
| Конфигурация | Константы, цвета, коэффициенты | `config/<name>.json`, переопределяется через `userData/config/<name>.json` |

Главной страницы нет. Оболочка (`src/renderer/shell`) не является модулем: она предоставляет меню, вход, настройки, диалоги и палитру команд.

**Системные модули** поставляются внутри приложения. **Пользовательские модули** — это папки, которые пользователь копирует в `userData/modules/` (в Настройках есть кнопки, чтобы открыть эту папку и повторно просканировать её). Реестр сначала читает системные модули; пользовательский модуль, который повторно использует `id` системного модуля, отклоняется с пояснением. Поле `source` (`system` или `user`) видно в Настройках.

## 2. Манифест

`manifest.json` обязателен в каждой папке модуля.

Страница:

```json
{
  "id": "reaction",
  "kind": "page",
  "title": "Reaction",
  "version": "1.0.0",
  "description": "Reaction speed test",
  "order": 80,
  "entry": "index.html",
  "hideable": true,
  "i18n": true,
  "channels": ["reaction:*"]
}
```

Плагин:

```json
{
  "id": "rounded",
  "kind": "plugin",
  "title": "Rounded corners",
  "css": ["style.css"]
}
```

| Поле | К чему применяется | Правила |
|---|---|---|
| `id` | к обоим | `^[a-z][a-z0-9-]*$`, совпадает с именем папки, уникально, не `app`, `shell` или `shared` |
| `kind` | к обоим | `page` или `plugin` |
| `title` | к обоим | Подпись в меню или настройках (запасной вариант, когда словарь не используется) |
| `version`, `description` | к обоим | Необязательные строки |
| `order` | к обоим | Позиция в меню; по умолчанию `1000`, поэтому пользовательские модули идут последними |
| `hideable` | к обоим | По умолчанию `true`; пользователь может скрыть страницу или выключить плагин |
| `entry` | к странице | Входной HTML-файл, по умолчанию `index.html` |
| `channels` | к странице | IPC-каналы, которые модуль может вызывать: `domain:*` или `domain:action` |
| `i18n` | к странице | `true`, когда у модуля есть словари в `locales/`; тогда его заголовок и описание берутся из ключей `module.title` и `module.description` |
| `css` | к плагину | Один или несколько CSS-файлов внутри папки |

Сломанный манифест никогда не роняет приложение: модуль пропускается, а причина показывается в Настройках.

## 3. Изоляция и загрузка

Каждая страница выполняется в собственном `<iframe sandbox="allow-scripts allow-same-origin">` со своим origin, `bm://<id>`.

- У модуля нет доступа к `window.api` или к DOM оболочки. Его единственная связь с приложением — мост `postMessage`, доступный как объект SDK `bm`.
- Мост разрешает только каналы, объявленные в `channels` (плюс `storage:*`, всегда ограниченные собственным пространством имён модуля). Всё остальное завершается со статусом `403`.
- Ошибки и необработанные отклонения промисов сообщаются оболочке, которая показывает экран сбоя с кнопкой перезапуска; остальное приложение продолжает работать.
- Нативные `alert`, `confirm` и `prompt` блокируются песочницей. Используйте `bm.confirm`.
- Все iframe разделяют процесс рендерера, поэтому бесконечный цикл в модуле замораживает окно.

Файлы отдаются протоколом `bm://`. `bm://app/...` — корень рендерера (оболочка, SDK, общий CSS, вендорные файлы); `bm://<id>/...` — папка модуля. Ответы несут `Access-Control-Allow-Origin: *`, что позволяет импортировать ES-модули между origin.

## 4. SDK

```js
import { bm } from 'bm://app/sdk/bm.js';

await bm.ready;
```

| Член | Описание |
|---|---|
| `bm.ready` | Промис, который разрешается, когда соединение, тема, язык и часовой пояс инициализированы. Не используйте `bm` до его разрешения |
| `bm.invoke(channel, payload)` | Вызывает IPC-канал. Разрешается результатом; отклоняется с `Error`, у которой есть `message` и `status` |
| `bm.config(name)` | Читает объект конфигурации (любую конфигурацию, кроме приватной `app`) |
| `bm.confirm(text, options)` | Стилизованный диалог подтверждения; `options`: `confirmText`, `cancelText`, `danger`. Разрешается булевым значением |
| `bm.setPills(items)` | Задаёт маленькие метки справа в заголовке (массив строк, пустой массив очищает) |
| `bm.storage` | Хранилище документов (раздел 5) |
| `bm.t(key, params)` | Переводит ключ (раздел 6) |
| `bm.locale`, `bm.language` | Локаль BCP 47 (для `toLocaleString`) и код языка |
| `bm.clock` | Время в часовом поясе пользователя (раздел 7) |
| `bm.theme` | `{ name, colorScheme, variables, chart: { text, grid } }` |
| `bm.onTheme(fn)` | Подписывается на изменения темы; возвращает функцию отписки |

Сообщения между модулем и оболочкой несут маркер `biomashine-bridge` и один из типов `hello`, `init`, `theme`, `invoke`, `config`, `confirm`, `pills`, `crash`, `response`. Оболочка отвечает на `hello` сообщением `init`, которое содержит тему, URL стилей плагинов, набор строк модуля и часовой пояс.

## 5. Хранилище документов

`bm.storage` хранит JSON-документы в именованных коллекциях. Оно существует, чтобы модуль мог сохранять данные без какого-либо кода главного процесса. Документы изолированы по модулю и включаются в экспорт данных.

| Вызов | Результат |
|---|---|
| `list(collection)` | `Promise<Document[]>` в порядке создания |
| `get(collection, id)` | `Promise<Document>`; отклоняется с `404`, если отсутствует |
| `insert(collection, data)` | `Promise<number>` (новый id) |
| `update(collection, id, data)` | Заменяет `data` целиком |
| `remove(collection, id)` | Удаляет один документ |
| `clear(collection)` | `Promise<number>` (количество удалённых документов) |

Документ — это `{ id, data, createdAt, updatedAt }`. Имена коллекций соответствуют `^[a-z][a-z0-9_-]{0,39}$`. `data` должен быть простым JSON-объектом размером не более 262144 байт. Храните моменты времени как строки `bm.clock.timestamp()`, а не как объекты `Date`.

Системные модули с собственными таблицами используют вместо этого выделенные каналы (репозиторий и контроллер в `src/main`, миграция в `migrations/`).

## 6. Локализация в модулях

Модуль с `"i18n": true` поставляет `locales/ru.json` и `locales/en.json` и не содержит жестко закодированного видимого пользователю текста.

- **JavaScript:** `bm.t('status.saved')`, `bm.t('total', { n: 5 })` для `"Total: {n}"`, `bm.t('items', { count: 5 })` для форм множественного числа.
- **HTML:** `data-i18n="key"` заменяет текст элемента; `data-i18n-placeholder`, `data-i18n-title` и `data-i18n-aria-label` заменяют соответствующие атрибуты. Оставляйте текст по умолчанию внутри элемента в качестве запасного варианта.
- **Формы множественного числа:** значение может быть объектом с формами `zero`, `one`, `two`, `few`, `many`, `other` (обязательно `other`); форма выбирается с помощью `Intl.PluralRules` по параметру `count`. Русский требует `one`, `few`, `many`, `other`; английский — `one`, `other`.
- **Даты и числа:** используйте `toLocaleString(bm.locale)`; никогда не жестко кодируйте локаль.
- **Тексты конфигурации:** конфигурация, содержащая видимые пользователю имена, хранит ключи словаря в полях, оканчивающихся на `Key` (например, `titleKey`), и код вызывает `bm.t(item.titleKey)`.
- **Обязательные ключи:** `module.title` и `module.description`.
- **Общий словарь:** ключи в `src/renderer/shared/locales` (`common.*`, `unit.*`, заголовки тем и достижений) доступны каждому модулю без объявления.
- **Один ключ на предложение:** никогда не собирайте предложение из переведённых фрагментов.

Пользователи могут добавлять языки, помещая файл языка в `userData/locales`; словари модуля включаются в шаблон, экспортируемый из Настроек.

## 7. Время

Пользователь выбирает часовой пояс в Настройках. Модуль должен читать текущее время только из `bm.clock`:

| Вызов | Результат |
|---|---|
| `bm.clock.now()` | `Date`, чьи локальные геттеры (`getHours()`, `getDate()` и т. д.) показывают настенное время выбранного пояса |
| `bm.clock.today()` | `YYYY-MM-DD` |
| `bm.clock.timestamp()` | `YYYY-MM-DD HH:MM:SS`; храните это, а не строку ISO |

Рекомендуемый паттерн — один класс часов на модуль, который оборачивает `bm.clock`, чтобы ничто другое в модуле не вызывало `new Date()` или `Date.now()` для текущего момента.

## 8. Темы и UI-кит

Цвета берутся из CSS-переменных, определяемых активной темой: `--bg`, `--s1`, `--s2`, `--s3`, `--br`, `--br2`, `--t`, `--td`, `--tdd`, `--tddd`, `--wh`, `--overlay`, `--header-bg`. Используйте их вместо литеральных цветов, чтобы модуль работал в любой теме. Атрибут `data-theme` на `<html>` содержит имя темы.

`bm://app/shared/components.css` предоставляет небольшой UI-кит:

| Класс | Назначение |
|---|---|
| `bm-page` | Контейнер страницы |
| `bm-title` | Заголовок раздела с линией |
| `bm-card` | Карточка |
| `bm-row`, `bm-spacer` | Flex-строка и растягивающийся разделитель |
| `bm-muted`, `bm-label` | Приглушённый мелкий текст; подпись поля |
| `bm-input` | Input, select, textarea |
| `bm-btn` (`secondary`, `danger`) | Кнопки |
| `bm-list`, `bm-list-item`, `bm-empty` | Списки и пустое состояние |
| `bm-stats`, `bm-stat`, `bm-stat-label`, `bm-stat-value` | Плитки статистики |
| `bm-chart` | Контейнер графика фиксированной высоты |

Chart.js 3.8.0 доступен как `window.Chart` после загрузки `bm://app/vendor/chart.min.js` с помощью классического тега `<script>`. Берите цвета осей из `bm.theme.chart`, перестраивайте графики в `bm.onTheme` и храните цвета серий в конфигурации.

## 9. Плагины

Плагин предоставляет только CSS. Его таблицы стилей загружаются после стилей темы в оболочке и на каждой странице, поэтому правило равной специфичности в плагине побеждает. Плагины могут переопределять переменные темы (`:root { --br: #444; }`, или для каждой темы с помощью `:root[data-theme="light"]`), стилизовать классы UI-кита и стабильные селекторы оболочки (`.shell-header`, `.nav-link`, `.dialog`, `.dialog-btn`, `.settings-card`, `.settings-row`, `.palette`, ...), а также загружать локальные шрифты с помощью `@font-face`. Внешние URL и `@import` недоступны, так как приложение работает офлайн. Пользователь включает и выключает плагины в Настройках → Внешний вид.

## 10. Написание модуля-страницы

1. Создайте `src/renderer/modules/<id>/` (или `userData/modules/<id>/` для пользовательского модуля), содержащую `manifest.json`, `index.html`, `module.css`, `js/`, `locales/` и `README.md`.
2. В `index.html` подключите `bm://app/vendor/fonts/fonts.css`, `bm://app/shared/base.css`, `bm://app/shared/components.css`, если используете кит, свой собственный CSS, опционально `bm://app/vendor/chart.min.js` и `<script type="module" src="./js/main.js">`.
3. `js/main.js`:

```js
import { bm } from 'bm://app/sdk/bm.js';
import { MyModule } from './MyModule.js';

bm.ready.then(() => new MyModule(bm, document).start());
```

4. Поместите логику в классы: чистые вычисления без доступа к DOM, класс представления для работы с DOM, класс репозитория для вызовов каналов и оркестратор, который их связывает.
5. Сохраняйте данные через `bm.storage` (пользовательские модули) или через выделенные каналы (системные модули).
6. Стройте DOM с помощью `createElement` и `textContent`; не присваивайте данные `innerHTML`.
7. Опишите модуль в его `README.md`: назначение, каналы, конфигурации, файлы, поведение.

Пошаговые руководства, написанные для ИИ-ассистентов, находятся в [docs/ru/ai](../ai): `MODULE_GUIDE.md` для страниц и `PLUGIN_GUIDE.md` для плагинов.
