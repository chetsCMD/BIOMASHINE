# BIOMASHINE: модульная система

Всё на экране, кроме оболочки, — модуль. Этот документ — контракт для написания модуля: формат манифеста, модель изоляции, SDK, который видит модуль, хранилище, локализация, время, темизация и плагины. Об окружающей архитектуре — [Project Map.md](Project%20Map.md).

## 1. Виды модулей

| Вид | Что это | Расположение |
|---|---|---|
| Страница (`page`) | Экран с собственным пунктом меню, интерфейсом и данными | `src/renderer/modules/<id>/` (системный), `userData/modules/<id>/` (пользовательский) |
| Плагин (`plugin`) | Только CSS, применяется к оболочке и каждой странице | те же места |
| Конфиг | Константы, цвета, коэффициенты | `config/<name>.json`, переопределяется `userData/config/<name>.json` |

Главной страницы нет. Оболочка (`src/renderer/shell`) — не модуль: она даёт меню, вход, настройки, диалоги и палитру команд.

**Системные модули** идут вместе с приложением. **Пользовательские модули** — папки, скопированные пользователем в `userData/modules/` (в настройках есть кнопки открыть эту папку и пересканировать). Реестр читает системные модули первыми; пользовательский модуль, повторяющий `id` системного, отклоняется с объяснением. Поле `source` (`system` или `user`) видно в настройках.

## 2. Манифест

`manifest.json` обязателен в папке каждого модуля.

Страница:

```json
{
  "id": "reaction",
  "kind": "page",
  "title": "Reaction",
  "version": "1.0.0",
  "description": "Reaction speed test",
  "order": 80,
  "entry": "index.html",
  "hideable": true,
  "i18n": true,
  "channels": ["reaction:*"]
}
```

Плагин:

```json
{
  "id": "rounded",
  "kind": "plugin",
  "title": "Rounded corners",
  "css": ["style.css"]
}
```

| Поле | К кому | Правила |
|---|---|---|
| `id` | оба | `^[a-z][a-z0-9-]*$`, равен имени папки, уникален, не `app`, `shell` или `shared` |
| `kind` | оба | `page` или `plugin` |
| `title` | оба | Метка меню или настроек (фолбэк, если словарь не используется) |
| `version`, `description` | оба | Необязательные строки |
| `order` | оба | Позиция в меню; по умолчанию `1000`, чтобы пользовательские модули шли последними |
| `hideable` | оба | По умолчанию `true`; пользователь может скрыть страницу или выключить плагин |
| `category` | оба | Необязательный id встроенной категории (`body`, `mind`, `finance`, `knowledge`, `environment`, `other` или пользовательская); по умолчанию `other` |
| `entry` | страница | Входной HTML-файл, по умолчанию `index.html` |
| `channels` | страница | IPC-каналы, которые модуль может вызвать: `domain:*` или `domain:action` |
| `permissions` | страница | Необязательный `["notifications"]`, разрешающий каналы уведомлений |
| `i18n` | страница | `true`, когда у модуля есть словари в `locales/`; тогда его title и description берутся из ключей `module.title` и `module.description` |
| `css` | плагин | Один или несколько CSS-файлов в папке |

Сломанный манифест никогда не роняет приложение: модуль пропускается, а причина показывается в настройках. `modules:errors` возвращает причины структурированными объектами (`{ dir, source, key, params }`), которые контроллер переводит на текущий язык.

## 3. Изоляция и загрузка

Каждая страница работает в собственном `<iframe sandbox="allow-scripts allow-same-origin">` со своим origin, `bm://<id>`.

- У модуля нет доступа к `window.api` или к DOM оболочки. Единственная его связь с приложением — мост `postMessage`, выставленный как SDK-объект `bm`.
- Мост разрешает только каналы, объявленные в `channels` (плюс `storage:*`, всегда ограниченный пространством самого модуля). Всё остальное падает со статусом `403`.
- Ошибки и необработанные отказы промисов передаются оболочке, которая показывает экран падения с кнопкой перезапуска; остальное приложение продолжает работать.
- Нативные `alert`, `confirm` и `prompt` заблокированы песочницей. Используйте `bm.confirm`.
- Все iframe разделяют процесс рендерера, поэтому бесконечный цикл в модуле замораживает окно.

Файлы отдаются протоколом `bm://`. `bm://app/...` — корень рендерера (оболочка, SDK, общий CSS, вендор); `bm://<id>/...` — папка модуля. Ответы несут `Access-Control-Allow-Origin: *`, что позволяет ES-модульные импорты между origin.

## 4. SDK

```js
import { bm } from 'bm://app/sdk/bm.js';

await bm.ready;
```

| Член | Описание |
|---|---|
| `bm.ready` | Промис, разрешающийся, когда соединение, тема, язык и часовой пояс инициализированы. Не трогайте `bm` до этого |
| `bm.invoke(channel, payload)` | Вызывает IPC-канал. Резолвится результатом; отклоняется `Error` с `message`, `status` и, если есть, `code` |
| `bm.config(name)` | Читает объект конфигурации (любой конфиг, кроме приватного `app`) |
| `bm.confirm(text, options)` | Стилизованный диалог подтверждения; `options`: `confirmText`, `cancelText`, `danger`. Резолвится булевым |
| `bm.setPills(items)` | Задаёт маленькие метки справа в шапке (массив строк, пустой массив очищает) |
| `bm.storage` | Хранилище документов (раздел 5) |
| `bm.notify` | Уведомления модуля (`schedule`, `cancel`, `list`), требуют `"permissions": ["notifications"]` |
| `bm.t(key, params)` | Переводит ключ (раздел 6) |
| `bm.locale`, `bm.language` | Локаль BCP 47 (для `toLocaleString`) и код языка |
| `bm.clock` | Время в часовом поясе пользователя (раздел 7) |
| `bm.theme` | `{ name, colorScheme, variables, chart: { text, grid } }` |
| `bm.onTheme(fn)` | Подписка на смену темы; возвращает функцию отписки |

Сообщения между модулем и оболочкой несут маркер `biomashine-bridge` и один из типов `hello`, `init`, `theme`, `invoke`, `config`, `confirm`, `pills`, `crash`, `response`. Оболочка отвечает на `hello` через `init`, содержащий тему, URL стилей плагинов, набор строк модуля и часовой пояс.

## 5. Хранилище документов

`bm.storage` хранит JSON-документы в именованных коллекциях. Оно существует, чтобы модуль мог сохранять данные без какого-либо кода в главном процессе. Документы изолированы по модулю и попадают в экспорт данных.

| Вызов | Результат |
|---|---|
| `list(collection)` | `Promise<Document[]>` в порядке создания |
| `get(collection, id)` | `Promise<Document>`; отклоняется `404`, если нет |
| `insert(collection, data)` | `Promise<number>` (новый id) |
| `update(collection, id, data)` | Заменяет `data` целиком |
| `remove(collection, id)` | Удаляет один документ |
| `clear(collection)` | `Promise<number>` (удалённых документов) |

Документ — `{ id, data, createdAt, updatedAt }`. Имена коллекций соответствуют `^[a-z][a-z0-9_-]{0,39}$`. `data` — это обычный JSON-объект не больше 262144 байт. Моменты времени храните как строки из `bm.clock.timestamp()`, а не как объекты `Date`.

Системные модули со своими таблицами используют выделенные каналы (репозиторий и контроллер в `src/main`, миграция в `migrations/`).

## 6. Локализация в модулях

Модуль, у которого стоит `"i18n": true`, поставляет `locales/ru.json` и `locales/en.json` и не содержит захардкоженного видимого текста. Полное руководство по всей системе — в [Localization.md](Localization.md).

- **Обязательные языки.** Каждый модуль обязан поставить `locales/ru.json` и `locales/en.json` — это языки из `app.json` → `i18n.required`. Другие встроенные языки необязательны; если файл для другого языка присутствует, он должен покрывать те же ключи, что и эталонный язык (`i18n.reference`, сейчас `ru`). Частичный файл — ошибка: `npm test` и `npm run i18n -- check` падают. Отсутствующие ключи добираются в рантайме по цепочке, описанной в [Localization.md](Localization.md) §3.
- **JavaScript:** `bm.t('status.saved')`, `bm.t('total', { n: 5 })` для `"Всего: {n}"`, `bm.t('items', { count: 5 })` для форм множественного числа.
- **HTML:** `data-i18n="key"` заменяет текст элемента; `data-i18n-placeholder`, `data-i18n-title` и `data-i18n-aria-label` заменяют соответствующие атрибуты. Оставляйте текст по умолчанию внутри элемента как фолбэк.
- **Формы множественного числа:** значение может быть объектом с формами CLDR `zero`, `one`, `two`, `few`, `many`, `other` (`other` обязателен; значение может использовать только формы, которые реально определяет его локаль). Форма выбирается через `Intl.PluralRules` по параметру `count`. Русскому нужны `one`, `few`, `many`, `other`; английскому — `one`, `other`; польскому — `one`, `few`, `many`, `other`; арабскому — `zero`, `one`, `two`, `few`, `many`, `other`.
- **Даты и числа:** `toLocaleString(bm.locale)`; никогда не хардкодьте локаль.
- **Тексты в конфигах:** конфиг, содержащий видимые пользователю имена, хранит ключи словаря в полях с суффиксом `Key` (например, `titleKey`), а код зовёт `bm.t(item.titleKey)`.
- **Обязательные ключи:** `module.title` и `module.description`.
- **Общий словарь:** ключи в `src/renderer/shared/locales` (`common.*`, `unit.*`, названия тем и достижений) доступны каждому модулю без объявления.
- **Один ключ на предложение:** никогда не собирайте предложение из переведённых кусков.
- **Ошибки бэкенда:** если модуль вызывает IPC-канал, ответ при ошибке несёт `code` (ключ словаря) рядом с `message`. Предпочитайте `error.code`, когда нужна стабильная точка привязки; `error.message` уже переведён на язык пользователя.

Пользователи могут добавлять языки, кладя языковой файл в `userData/locales`; словари модуля попадают в шаблон, экспортируемый из настроек.

## 7. Время

Пользователь выбирает часовой пояс в настройках. Модуль должен читать текущее время только из `bm.clock`:

| Вызов | Результат |
|---|---|
| `bm.clock.now()` | `Date`, локальные геттеры которого (`getHours()`, `getDate()` и т.д.) показывают настенное время выбранного пояса |
| `bm.clock.today()` | `YYYY-MM-DD` |
| `bm.clock.timestamp()` | `YYYY-MM-DD HH:MM:SS`; храните именно это, а не ISO-строку |

Рекомендуемый паттерн — один класс часов на модуль, оборачивающий `bm.clock`, чтобы больше ничего в модуле не звало `new Date()` или `Date.now()` для текущего момента.

## 8. Темизация и UI-кит

Цвета берутся из CSS-переменных, определённых активной темой: `--bg`, `--s1`, `--s2`, `--s3`, `--br`, `--br2`, `--t`, `--td`, `--tdd`, `--tddd`, `--wh`, `--overlay`, `--header-bg`. Их использование держит модуль читаемым в любой теме, поэтому они — выбор по умолчанию; это не ограничение. Приложение не заставляет пользователей в один стиль: модуль (или просьба пользователя к ассистенту) может использовать любые литеральные цвета, шрифты и размеры. Атрибут `data-theme` на `<html>` хранит имя темы.

`bm://app/shared/components.css` даёт небольшой UI-кит:

| Класс | Назначение |
|---|---|
| `bm-page` | Контейнер страницы |
| `bm-title` | Заголовок раздела с линией |
| `bm-card` | Карточка |
| `bm-row`, `bm-spacer` | Flex-строка и растягивающийся спейсер |
| `bm-muted`, `bm-label` | Приглушённый мелкий текст; метка поля |
| `bm-input` | Input, select, textarea |
| `bm-btn` (`secondary`, `danger`) | Кнопки |
| `bm-list`, `bm-list-item`, `bm-empty` | Списки и пустое состояние |
| `bm-stats`, `bm-stat`, `bm-stat-label`, `bm-stat-value` | Плитки статистики |
| `bm-chart` | Контейнер графика фиксированной высоты |

Chart.js 3.8.0 доступен как `window.Chart` после загрузки `bm://app/vendor/chart.min.js` классическим тегом `<script>`. Цвета осей берите из `bm.theme.chart`, перестраивайте графики в `bm.onTheme`, а цвета серий храните в конфиге.

## 9. Плагины

Плагин даёт только CSS. Его стили загружаются после стилей темы, в оболочке и на каждой странице, поэтому правило равной специфичности в плагине побеждает. Плагины могут переопределять переменные темы (`:root { --br: #444; }` или по теме через `:root[data-theme="light"]`), перекрашивать классы UI-кита и стабильные селекторы оболочки (`.shell-header`, `.nav-link`, `.dialog`, `.dialog-btn`, `.settings-card`, `.settings-row`, `.palette`, ...) и подключать локальные шрифты через `@font-face`. Внешние URL и `@import` недоступны, потому что приложение офлайновое. Пользователь включает и выключает плагины в Настройках → Внешний вид.

## 10. Написание модуля-страницы

1. Создайте `src/renderer/modules/<id>/` (или `userData/modules/<id>/` для пользовательского модуля) с `manifest.json`, `index.html`, `module.css`, `js/`, `locales/` и `README.md`.
2. В `index.html` подключите `bm://app/vendor/fonts/fonts.css`, `bm://app/shared/base.css`, `bm://app/shared/components.css` если используете кит, свой CSS, опционально `bm://app/vendor/chart.min.js` и `<script type="module" src="./js/main.js">`.
3. `js/main.js`:

```js
import { bm } from 'bm://app/sdk/bm.js';
import { MyModule } from './MyModule.js';

bm.ready.then(() => new MyModule(bm, document).start());
```

4. Держите логику в классах: чистые расчёты без доступа к DOM, класс-представление для работы с DOM, класс-репозиторий для вызовов каналов и оркестратор, который всё связывает.
5. Сохраняйте данные через `bm.storage` (пользовательские модули) или через выделенные каналы (системные модули).
6. Стройте DOM через `createElement` и `textContent`; не присваивайте данные в `innerHTML`.
7. Опишите модуль в его `README.md`: назначение, каналы, конфиги, файлы, поведение.

Пошаговые руководства для ИИ-ассистентов живут в [docs/ru/ai](../ai): `MODULE_GUIDE.md` для страниц и `PLUGIN_GUIDE.md` для плагинов.
